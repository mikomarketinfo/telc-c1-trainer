# Пайплайн генерации тестов из реальных статей
Версия: 1.0 (черновик на согласование, до написания кода)

## 0. Важное техническое ограничение — прочитать в первую очередь

TELC C1 Engine — **статический сайт** (HTML/CSS/JS, без бэкенда, задеплоен на GitHub Pages).
Это значит:

- Браузер **не может** сам скачать статью с dw.com/zdf.de/tagesschau.de через `fetch()` —
  эти сайты не отдают CORS-заголовки для чужих доменов. Это не ограничение движка, а
  fundamental ограничение браузера — обойти его без собственного сервера-прокси нельзя.
- Без backend-API (вы просили "без API") у нас нет способа полностью автоматизировать
  процесс "нажал кнопку в приложении — получил новый тест из свежей статьи".
- Реалистичная архитектура на этом этапе: **генерация — оффлайн-процесс** (в диалоге со
  мной или другой LLM), а сам сайт остаётся простым потребителем готовых JSON-файлов,
  как сейчас. Это не костыль, а стандартная практика: контент готовится отдельно от
  runtime-приложения (как в любом статическом генераторе сайта).
- Если в будущем захотите настоящую автоматизацию "по кнопке" — это уже требует хостинга
  (Cloudflare Worker / Vercel Function и т.д.) и, скорее всего, платного API. Пока
  оставляем это вне текущего этапа, как вы и просили.

Итог: пайплайн ниже описывает **повторяемый ручной/полуручной процесс**, который я (или вы)
выполняете перед тем, как закоммитить новый JSON-тест в `data/`.

## 1. Обязательные правила (copyright и качество)

1. **Никогда не копировать текст статьи дословно.** Даже 2-3 абзаца подряд — нарушение
   авторского права DW/ZDF/Tagesschau и т.д. Разрешено:
   - пересказывать факты своими словами;
   - использовать отдельные цифры/статистику (факты не защищены copyright, конкретные
     формулировки — защищены);
   - максимум 1 короткую цитату (до ~15 слов) на источник, и только если дословность
     принципиальна (прямая речь политика и т.п.) — для учебных текстов практически не
     нужно.
2. **Один тест — по возможности несколько источников.** Текст, собранный из фактов 2-3
   статей и написанный заново, надёжнее по copyright и часто качественнее одной
   пересказанной статьи.
3. **Уровень C1, не выше и не ниже.** Целевые ориентиры:
   - предложения средней длины 15-25 слов, но с вариацией;
   - используется пассив, конъюнктив II, номинализация, сложные коннекторы
     (obwohl/dennoch/indem/sodass), Genitiv-атрибуты;
   - лексика: абстрактные существительные, устойчивые сочетания (Nomen-Verb-Verbindungen),
     профессиональная/общественно-политическая лексика — но без чистого жаргона
     (не "Bilanzsumme", а "wirtschaftliche Auswirkungen").
4. **Указывать источники честно.** В поле `generator.source` — список тем/ссылок, на
   основе которых собран текст, и пометка, что текст написан заново, а не скопирован.
   `validated: false` до прохождения шага 5 (проверка).

## 2. Формат по модулям экзамена (что генерировать по-разному)

| Модуль | Объём текста | Число вопросов/вариантов | Тип текста |
|---|---|---|---|
| Sprachbausteine | 1 связный текст ~150-250 слов, 10-15 пропусков | 4 варианта на пропуск | нейтральный, описательный |
| Leseverstehen Teil 1 | 5 коротких заметок по 60-90 слов | 10 заголовков на подбор (2 лишних) | разнородные новости |
| Leseverstehen Teil 2 | 1 текст ~350-450 слов | 5 вопросов × 3 варианта | аналитическая статья с фактурой |
| Leseverstehen Teil 3 | 1 текст-подборка мнений ~400-500 слов, 5-6 говорящих | 10 утверждений → сопоставить со спикером | явные "за"/"против" |

Для Teil 1 и Teil 3 движок пока не умеет рендерить — это будет отдельным шагом после
того, как утвердим этот процесс на Teil 2/Sprachbausteine (по аналогии с тем, что я уже
сделал).

## 3. Пошаговый процесс (что я делаю при генерации одного теста)

**Шаг 1. Выбор темы и источников**
- Беру тему из согласованного списка (см. предыдущее сообщение с распределением тем).
- Через `web_search` ищу 2-4 свежие статьи (последние ~6 месяцев) с сайтов из списка
  (ZDF, Tagesschau, DW, Deutschlandfunk, Spektrum, Zeit Wissen) плюс при нехватке
  материала — авторитетные вторичные источники (ifo, IW Köln, Destatis, DIHK, McKinsey,
  Bitkom и т.п. для фактуры/цифр).

**Шаг 2. Извлечение фактов, не текста**
- Из каждого источника выписываю 3-6 конкретных фактов/цифр/тезисов своими словами
  (никогда — абзацы целиком).
- Проверяю, что факты не противоречат друг другу; если противоречат — беру более
  свежий/авторитетный источник.

**Шаг 3. Написание оригинального текста**
- Пишу текст с нуля на основе выписанных фактов, ориентируясь на объём и стиль из
  таблицы в разделе 2.
- Для Sprachbausteine сразу закладываю разнообразие грамматических конструкций
  (не 10 предлогов подряд, а микс: предлоги/коннекторы/пассив/конъюнктив/местоимения).

**Шаг 4. Генерация вопросов**
- Sprachbausteine: заменяю целевое слово/конструкцию на пропуск, формирую 4 варианта
  (1 верный + 3 правдоподобных, но грамматически или семантически неверных в этом
  контексте — не абсурдных).
- Leseverstehen: формирую вопросы по схеме — 1× общая идея текста, 1-2× конкретная
  деталь, 1× причинно-следственная связь/вывод, 1× ещё деталь, 1× итоговая мысль текста.
  Дистракторы должны быть похожи на правду, но опровергаться текстом, а не быть
  случайными.

**Шаг 5. AI Validator (проверка перед публикацией)**
Автоматическая часть (уже есть в движке — `TestValidator.js`): проверяет структуру JSON
(обязательные поля meta/content/questions, что у каждого вопроса есть options/correct/skills).

Дополнительная смысловая проверка, которую нужно выполнять вручную/мной при каждой
генерации (чек-лист, пока без кода):
- [ ] У каждого вопроса ровно один явно верный вариант (нет двусмысленности)
- [ ] Ни один дистрактор не является скрыто тоже верным
- [ ] Текст соответствует объёму ± 15% от нормы модуля
- [ ] Ни одна фраза не совпадает дословно с источником (>10-12 слов подряд)
- [ ] Указаны все source-темы в `generator.source`
- [ ] Уровень CEFR ощущается как C1 (не B2, не C2) — субъективная, но обязательная проверка

**Шаг 6. Публикация**
- Файл кладётся в `data/<module>/<id>.json`, добавляется в `data/index.json`.
- `generator.validated` ставится `true` только после прохождения чек-листа шага 5.
- При необходимости — новые статьи в `data/knowledge/` под новые грамматические темы.

## 4. Что нужно от кода (следующий шаг, уже после вашего "ок")

Сам "движок генерации" в виде кода — это не нейросеть внутри сайта (это статический
сайт, без API мы не можем звать LLM из браузера), а **вспомогательные инструменты**:

- Скрипт-шаблон/чек-лист в `AI_GENERATION.md` (обновить существующий файл под этот
  процесс, а не описанный там ранее "текст с нуля без источников").
- Расширение `TestValidator.js` — добавить проверку `generator` блока (source/validated
  обязательны для тестов с `generator` полем) и базовую эвристику длины текста по модулю.
- Возможно — небольшой Node-скрипт для локальной проверки (не в браузере, а как
  dev-инструмент), который прогоняет все JSON в `data/` через валидатор разом — чтобы
  не проверять руками каждый раз перед коммитом.

## 5. Что не входит в этот этап (сознательно отложено)

- Teil 1 (заголовки) и Teil 3 (мнения) — новые типы рендерера, делаем после утверждения
  этого процесса на уже работающих модулях.
- Настоящая автоматизация "по кнопке в приложении" — требует backend и/или платный API,
  вне рамок текущей задачи.
- Аудио/Hörverstehen — отдельный трек, как договорились, в конце.
